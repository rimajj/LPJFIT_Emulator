### Added
- **The emitted restart file now has competitors, and it loses to all of them.** It had only ever been scored against the truth (vegetation carbon off by 0.534). Given nulls, on 20 cells and all 22 scored quantities, the best synthesis version scores **0.702** where handing the model **a random neighbouring cell's real forest scores 0.786**. The nulls are all self-consistent forests; a file assembled from donors to match predicted height and wood-density quantiles matches those marginals and inherits everything else from whichever donor was picked. Matching marginals does not make a forest. Record: `docs/decisions/20260909-X-synthesised-restart-is-beaten-by-a-random-neighbour.md`.
- `scripts/exp_derive_nulls_restart.py` — derives the restart-drift nulls from files already on scratch, in about two seconds, with no new model run. Adding a run directory to `VARIANTS` scores the next synthesis iteration against its nulls instead of against nothing.

### Changed
- **The later synthesis versions are a real gain, and the first version's one-year collapse is fixed:** 0.582 → 0.702 from line T's widened donor pool. `synth-v0` had been dynamically rejected — it shed 2.5 MB of stems in a single year and its biomass, leaf area index and stem count all fell to a 0.00 pass rate. The later versions track the control.
- **Running the real model forward is a no-op, not a repair:** +0.016 and −0.005 for the two working versions, with the sign flipping between the two acceptance bands. That kills the "short polish run" fallback as a repair mechanism — the lever belongs at year 0, in the synthesis.
- **`X4` is deliberately NOT sealed.** On this 20-cell contiguous block the conjunctive statistic is pinned at its 0.05 granularity floor for every arm, and all four nulls collapse into 0.786–0.845 because the block is one neighbourhood. A test whose nulls cannot be told apart before it runs has no power, so sealing would pre-register a guaranteed `invalid`. What it needs first is written down.
- **t3 as worded in `PLAN.md` is unrunnable** and two corrections are requested of the integrator. "20 years with no drift beyond the two-seed spread" fails on the REAL model in 71 % of cells, because a cell's interannual variability (median 16.5 % of its level) is larger than the band (median 10 %). The state's own drift is a median 1.75 % over 20 years and is not the problem — the noise is. On a 20-year window mean a real restart passes in 90.9 % of cells, and that, not 1.0, is the ceiling.

### Added
- **A third sealed pre-registration, `X-20260908-heldout-forcing-leg`.** A map fitted on the 1970–1999 climate is handed the 2071–2100 climate of the **low-emissions** leg — a leg whose state it has never seen, in any cell — and asked for the year-2100 forest. It is scored with the same statistic, the same 22 quantities and the same code as the sealed map test, so the two numbers are directly comparable: one scores the leg the map was fitted on, the other a leg it never saw.
- **The competitor that matters is persistence**: hand back the same cell's own present-day forest. Derived before the run at **0.033749** of cells inside the acceptance band on all 22 quantities at once — against 0.005426 for the geographically nearest cell, 0.004688 for the climatically nearest analogue, 0.000632 shuffled and exactly 0.000000 for the average forest. So the model must reach **0.0837** to pass, more than double the 0.0361 it scores on the leg it was fitted on.
- **A non-circular acceptance band** (`acceptance_band_transferred` in `src/vegemu/score.py`). The band has until now been derived from the same two model runs whose average is the truth, so "predict one run" sat at exactly half a band and could not fail. Taking the tolerance from a *different* leg breaks that: one run of the real model now scores **0.538490** rather than 1.000000, and that is what "perfect" means on this metric. The transfer is licensed by measurement — over the 56,950 scored cells the two legs' run-to-run spreads agree to within 6 % on every summary — and the same-leg band is reported beside it, never instead of it.
- `tests/test_band.py` — the circularity as an executable property: under a same-leg band a single model run is inside the band in *every* cell by construction; under a transferred band it can miss. Also pins that transferring a leg onto itself reproduces the old band bit-identically, so no committed number moved.
- `scripts/exp_derive_nulls_leg.py` — the same derive-before-you-run discipline for a held-out forcing leg, including the check that a leg's two runs are actually two runs.

### Fixed
- **The main branch was failing three of its nine checks, and nothing in the project was able to notice.** Every check here only runs when a commit touches the files it cares about, and the only commits the main branch had received since its history was replaced were documents — so the checks that compile, type-check and test the code had never once run on it. Run by hand, they come back: green on six, **red on formatting, type-checking and the test suite**. None of it is new: all three were merged in from the data line and the training line, whose own checks had never run either. The formatting and type errors are in files only those lines are allowed to edit, and both lines have been told exactly which; the main branch stays red until they merge the fixes.
- **Two of the failures were the checking machinery's own fault, and are fixed here.** The type checker was failing on a missing helper package for reading YAML that the project has declared as a development dependency since the day it was written — the check just installed its tools by hand and never installed that one. And two tests ask git for the commit before this one, which does not exist in the shallow one-commit copy the test runner makes by default; the tool under test correctly answered "I cannot compute a difference" and the test correctly failed. The test runner now fetches the full history. In both cases the environment was wrong, not the code.
- **The tool that polls for check results had never worked in this project at all.** It builds the address to ask about from the remote's URL, and for the address form this project uses (`git@host:owner/repo`) it dropped the **owner**, so every request asked about a repository that does not exist and got "not found" back. Worse, "not found" was treated as a passing network glitch and retried until the timeout, whose message is *"still pending"* — so a permanently wrong address and a genuinely slow check printed the same words. Both are fixed, with tests: the owner survives all four URL forms, and a refusal from the server now stops immediately and says what to check.
- **That is the same defect in a third place, and it is now written down as a class.** Three times in this project one reassuring message has covered two situations that mean opposite things: an empty list of changes that actually meant *the list could not be computed*; a score of zero that actually meant *no score was reported*; and a "not found" that read as *still waiting*. It is recorded in the project memory as a shape to suspect first whenever output looks calm.

- **Both escape hatches on the guard that protects the shared login machine were dead advice.** That guard blocks heavy computation on the login machine and blocks any job submission that would skip the job ledger, and each refusal ends by telling you how to override it for a genuine exception — by putting `ALLOW_LOGIN_HEAVY=1` (or `ALLOW_RAW_SBATCH=1`) in front of the command. Neither could ever work: the guard runs in the assistant's own environment, not in the shell the command is about to run in, so a setting written in front of the command was invisible to it. It now recognises that form, which matters because the "is this heavy?" test is a keyword search over the whole command — in a project about corpora and training, ordinary commands mention those words, and handing a message to another work line was refused as a heavy computation with an override that did not exist. **All eleven of the guard's decisions are now pinned by a test**, including that the two overrides open, and one promise in its own header comment that the code never kept (importing the deep-learning library on the login machine) is now enforced as documented.

### Changed
- **Merging now refuses to proceed past a failing check, instead of advising against it.** The merge script used to print the list of checks a change would trigger and then say, in words, "if any of those are not green, stop now" — and three merges went past it. It now asks for the actual results on the exact commit being merged and stops unless all of them passed; "I could not find out" counts as a stop too, because a commit whose status is unknown is not a commit that passed. A documents-only change triggers nothing and so passes instantly, which is what keeps this from blocking everyday work. There is a deliberate override that requires a written reason, and the reason is recorded permanently in the merge commit itself — a guard whose bypass leaves no trace is a guard that gets bypassed.
- **The merge script also checks the main branch after pushing to it**, and reports failure loudly. It cannot undo a merge that has already happened, but the main branch's health is now a stated fact rather than a closing paragraph of advice that nobody acted on. Doing this needed a small fix of its own: asking "what does this branch add over the main branch?" is the right question for a work line and a meaningless one for the main branch itself, where the answer is always "nothing", so the comparison now starts from where the main branch stood before the push.
- **Recorded**: `docs/decisions/20260908-INT-main-was-red-and-no-one-could-tell.md`, including the technique for getting a verdict out of a commit whose push triggered no checks at all — every check here can be started by hand, which is the remedy for the force-push trap noted below.

### Added
- **The emulator** (`src/vegemu/models/emulator.py`): one gradient-boosted head per scored quantity, fitted per spatial fold. Predicting the 10th/50th/90th percentile of each trait directly IS a non-parametric distribution head, which is why this and not a parametric kernel is the first model; its limits — marginal quantiles predicted independently, no stochastic per-stem head — are stated in the module.
- **A restart file the real LPJmL-FIT loads and runs.** `scripts/synth_restart.py` emits one by template-conditioned synthesis with rank-matched stem transplant: 20 cells, 47.9 MB, 9,506 stems placed against 9,506 requested, achieved height and wood-density distributions within 0.3 % of the prediction. The model's own words: *"lpjml successfully terminated, 20 grid cells processed."*
- **Twelve validation figures** (`scripts/plot_validation.py`), covering both what works and what does not.
- **Both verdicts, both FAIL, and every null returned its pre-registered value** — so neither is `invalid`: the apparatus did exactly what was declared and these are clean failures of the model, not of the measurement.
- **The map test**: the emulator reaches 0.0361 of cells inside the acceptance band on all 22 quantities at once, against 0.0212 for the climatically nearest analogue and 0.0187 for the nearest cell. It beats every null by 1.7×, but the gate asked for a margin of 0.050 and it delivered 0.0149.
- **The kill test**: −0.727 against 0.000 for predicting no change. Diagnosed rather than merely reported — stem count carries real response skill (+0.35) and leaf area some (+0.10), while soil carbon is four times worse than nothing, because the response is obtained by DIFFERENCING two level predictions and that only works where the true change is large compared with the level error. Record: `docs/decisions/20260908-X-response-fails-on-one-climate-per-place.md`.
- **The pre-declared 5° sensitivity check turned out to be load-bearing**, not a footnote: at 5° blocks the address null flips from −0.142 to +0.120 on the response and would trip the no-power rule. The 15° primary is what makes the result mean anything.

### Changed
- **The emitted state loads but its carbon is half right** — vegetation carbon 2,561 against the control's 5,035 gC/m², a median relative difference of 0.534 — and the cause is attributed, not guessed: for the same cells the emulator predicts above-ground biomass to 12 %, so the fault is that carbon is not one of the donor-matching targets. ### Fixed
- **The per-stem `litter` byte is an INDEX into its patch's litter list, not a value.** A transplanted stem carried its donor patch's index and the C refused the file with `ERROR195`. No round-trip test can catch this: within one record the index is always consistent, and it breaks only when a stem moves between patches. Every comparison in `tools/_experiments.py` now tests `is not None`.

### Added
- **Two sealed pre-registrations.** `X-20260908-climate-state-map` asks whether a 30-year climate summary alone reproduces LPJmL-FIT's forest state inside the acceptance band on 22 quantities conjunctively — stem count, three stocks, six trait medians and both tails of each of those six trait distributions. `X-20260908-warming-response` is **the kill test**: a model fitted on the historical leg only, shown the same cell's climate for 1970–1999 and for 2071–2100 under high emissions, must explain the model's own simulated change better than predicting no change at all.

- **The address null is a spatial nearest neighbour rather than a latitude/longitude regression**, because a weak null is worse than no null — and because a nearest neighbour has no free parameters, so its required value can be derived before any model exists.
- `src/vegemu/dataset.py` — one loader, so the nulls line X derives are the nulls line T measures.
- `tests/test_folds.py` — the pre-registrations' leakage checks as executable assertions: no spatial block is split across folds, the feature matrix contains no address/state/CO₂ column, and every null is exactly reproducible.

- **The corpus builder** (`src/vegemu/corpus/`, `scripts/corpus_build.py`). Per-cell state summaries read straight out of the restart files — counts, stocks, the growth-failure counter, the height distribution, PFT composition and five quantiles of each of eight per-stem traits — and per-cell 30-year climate summaries read out of the `.clm` forcing. Both seeds of all three legs, so the acceptance tolerance (the model's own two-seed spread) is measured rather than assumed. Provenance, including each source file's decoded header, ships with every table.

### Changed
- **The 1000-year spin-up has not converged.** Global vegetation carbon is 719 Pg C at year 200, 735 at year 500 and **890 at year 1000**, still rising at **+6.5 %/century**; 58 % of vegetated cells are outside their own acceptance band at the end of the run and 73 % are still rising faster than 1 %/century. So the stored state is not an equilibrium but *the state the model's standard spin-up protocol reaches*, and `PLAN.md`'s hoped-for 3.3× cut to every corpus budget is refuted — a 300-year spin-up would differ by 22 %. Record: `docs/decisions/20260908-D-spinup-is-not-converged.md`.
- **The noise floor, measured on this data:** the two-seed relative spread of end-of-spin-up vegetation carbon has a median of 3.41 %, a p90 of 13.6 % and a p99 of 42.4 % across 61,700 vegetated cells. Interannual variability of the annual series is 16.5 % of the level.
