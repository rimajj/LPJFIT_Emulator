### Fixed

- **The emitted restart file's roster was valid stem by stem and not viable as a forest, and that — not the synthesis — is what halved its carbon.** Donors were chosen by nearest height and wood density over a pool deliberately spanning biomes, and the tree TYPE was never looked at, so 31 % of the stems written into a block of twenty temperate European cells were tropical broadleaved evergreen: a type those cells' own real state never contains. The model loaded the file, ran, did not abort under `-DSAFE`, and then killed every one of them in the first year (`mort_temp = 1.000`, certain death, because LPJmL-FIT charges a tropical evergreen a stress day for every day below 12.5 °C and kills at 73). Half the roster and two thirds of the carbon went with them. Tree type is now COPIED from the target cell's own template roster at the matching size rank, and the trait match happens only among donors of that type.
- **The previous record's attribution was wrong and is superseded.** The file that was written held above-ground biomass 6.7 % HIGH (4,030 against 3,777 gC/m²), not 50 % low; the loss happened during the model run. Reading the state summary of the emitted file, instead of inferring it from the run's output, is what settled it. So adding biomass to the donor-matching objective — the previously recommended next step — would have chased a bias that was not there.

### Added

- **A viability assertion, and it is not a round-trip** (`tests/test_synth_admissibility.py`): no synthesised stem may be of a type the target cell's own real state never holds. A byte-identical round-trip validates a layout; this is a cross-reference between a record and its cell's climate, so it needs its own check. Two layers, synthetic and against the real 20-cell block in the exact configuration that failed.
- **`inadmissible_placed`, per cell, and it must be zero** — reported by the synthesiser and printed by the driver, so the fault surfaces before a model run rather than after one.
- **A donor pool chosen by proximity, with the target block excluded.** Nine biome-spanning cells plus a band of 20 cells either side of the block: 25,424 donor stems against 6,745. Cell 42490 was removed from the biome list because it sits inside the default block, and the pool builder now refuses any donor inside the block being written — a donor from the target block scores the synthesis against itself. Proximity rather than "the cells richest in what this block lacks", which would make the result a selected maximum.

### Changed

- **The emitted state is now stationary under the real model, and its carbon matches to 9 %.** After one year, median |emulated − control| / control over the 20 cells: vegetation carbon 0.543 → **0.091**, above-ground biomass 0.610 → **0.092**, stems per patch 0.490 → **0.088**. Vegetation carbon over the first year now goes ×1.04 against the control's ×1.02, where it went ×0.35 before. Basis: 20 cells of 54,020, one region, present-day climate — **not** the acceptance test, and the conjunctive test still fails (0 of 20 cells inside the band on all 22 quantities at once, median 15 of 22). Record: `docs/decisions/20260909-T-the-roster-was-valid-but-not-viable.md`.
- **Matching more traits makes it worse, measured rather than assumed.** Five traits instead of two hits the three medians it adds and wrecks the tails (wood density's 90th percentile 0.063 → 0.167, above-ground biomass 0.091 → 0.154; 11 of 22 quantities worse, 6 better). A donor is one real stem carrying one value of every trait at once, so asking it to sit at the same quantile of five distributions is asking for a stem that need not exist. The match set is now a parameter (`--match-traits`) so the next attempt is a measurement.
