### Added
- **The machinery to produce the reference answers the finished tool must be checked against — for every location, under today's climate and both future scenarios — is built and tested, but the full run is not started.** The owner's test of "finished" is that the tool matches the original model everywhere, today and under climate change. Nothing already on disk can serve as that reference: the stored settling-in runs had rising CO₂ in their last 300 years, and the stored future runs start from today's forest and run forward for 80 years, which is not the settled forest under a future climate. So the reference has to be made fresh, by running the original model's full 1,000-year settling-in at every one of the 67,420 land locations under three climates (1970–1999 observed, and 2071–2100 under the low- and high-emissions scenarios), twice each with different random seeds, exactly the way the training simulations were made. The new tool does all the bookkeeping for that: it cuts each location's 30 years of climate out of the global files, writes the model's settings, lists the runs in balanced batches, checks every file exists before anything is spent, judges each run by the model's own "finished successfully" line, and turns the results into a table with exactly the same columns as the training table. **The CO₂ level the reference is settled at is a setting, not a decision this change makes** — it defaults to the pre-industrial level the training simulations used, and which level the reference should use is the owner's call. **Projected cost of the full run, both seeds: about 24,200 core-hours of model time, 25,500 charged** (about 12,100 and 12,700 per seed), in 54 batch jobs of roughly 2 hours each, about 0.9 TB of disk and about 3.9 million files. Run the old way it would have been charged about 46,000. That projection comes from how long the 6,000 training simulations actually took; checked against the 200 locations where both exist, it is right on average (within 2 %) but often off by up to a factor of two for a single location, and for the two future climates it could not be checked at all beyond 16 trial runs (within 3–6 %).
- **The same-simulation check passes: at the locations shared with the training simulations, today's-climate reference runs come out identical to the byte.** A small end-to-end trial ran 8 locations × 3 climates, all 24 to completion. For the 3 of those locations that are also in the training set (central Germany, the Amazon, Siberia), the climate files and the final forest state are byte-for-byte what the training run produced, and the decoded table row matches the training row in every column. That is what makes the reference comparable to the training data — they are the same simulation, not just similar ones. The trial was also the test of the cheaper batching below: 24 runs through 6 processors used 93 % of what was charged, against 53 % the old way.
- **The one outstanding question about the model's two program versions is settled: they produce byte-identical results.** Part of the stored reference data came from an older build of the original model (5 February) and the training simulations from a newer one (12 August). The difference was believed harmless from reading the code, but had never been tested. Running one forested location for one year from the same starting state, the two builds wrote identical final states, identical per-tree output and identical carbon and water totals, and a repeat of the newer build matched too. It covers one location and one year of an ordinary run, not every code path. Written up in decision record `20260923-D-the-two-builds-write-byte-identical-restarts`.

### Changed
- **Batch jobs of many short model runs are now charged for the time they actually use.** Before, every run in a batch held its own processor until the slowest one finished, so the 6,000 training simulations were billed for 1.9 times the computing they used. Asking for fewer processors than runs now makes the batch start each next run as soon as one ends. The ledger that tracks jobs now also records the estimated cost, the deadline for collecting results, and two optional output settings that change what the model writes.

### Fixed
- **Runs of the older model build would have been recorded as failures even when they succeeded.** The model announces success with a line starting with its own file name, and the older build's file has a different name, so the check that looked for the newer build's name could never match it. The check now uses whichever build was actually run.
- **"The 54,020 locations with trees" now has a precise, reproducible definition.** It is the set of locations with at least one living tree (not grass) in the older per-tree output table, which leaves out trees under 5 m. Counting every location in that table gives 63,119, because it lists grasses too. The reference plan marks all three ways of counting side by side (56,986 locations with any tree at all in the settled state, 52,198 with a tree at least 5 m tall, and the 54,020).
