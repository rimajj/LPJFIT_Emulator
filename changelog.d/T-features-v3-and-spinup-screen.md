### Added
- **New climate inputs built from the day-by-day weather, and a trial run of possible improvements to the settled-forest predictor: together they lift it from 58 % to 66 % on locations it never saw — an exploratory result, not yet a registered one.** Until now the tool saw only monthly averages and a few summary numbers of the climate. It now also sees 120 quantities computed from the daily weather the way the original model experiences it: a simple soil-water budget run for five different rooting depths (so it can tell when deep roots pay off), how long dry spells last, how much drought stress builds up on hot, dry days, and how often each tree type's own cold, heat and warmth limits — read from the original model's parameter files — are crossed. None of them uses the location or CO₂. They exist for every one of the 6,000 pilot simulations and for all 67,420 land cells under the historical climate and both future scenarios. **A hard check passed exactly:** for the 200 unperturbed pilot runs, the new inputs computed from each run's own weather file are identical, to the last digit, to those computed from the global weather file.
- **How the options were compared, and what won.** The comparison was done on three of the five groups of locations only; the other two were kept aside and never used to choose. Starting from the registered model (which the new code reproduced exactly), three changes each earned their place by more than the noise: the new daily-weather inputs (+0.056), first predicting the mix of tree types and feeding that to the tree-trait predictions (+0.012), and re-tuned model settings (+0.026, an optimistic figure because the tuning was scored on the same groups). Three did not: predicting traits on a log scale or as a median plus spreads (both worse), averaging five model copies (+0.001), and removing the soil-texture inputs (no change). On the two groups kept aside, the chosen version explains **66 %** of the variation against **58 %** for the registered version on the same locations; the best possible, given that two runs of the original model already differ, is about **94 %**. The weakest parts improved most: rooting depth 0.28–0.37 → 0.42–0.51, wood density 0.38 → 0.56, leaf longevity 0.35 → 0.52. It still almost never gets all 22 quantities within 10 % at once. **This is a trial run, not a result:** 74 of 54,020 locations, one run each, no future scenario.
- **More locations would still help a lot.** Training on a quarter, half, three quarters and all of the available locations gives a steady gain of about 0.07 each time the number of locations doubles, with no sign yet of levelling off. That supports running the planned larger set of simulations (1,000 locations), though stretching this trend five-fold beyond what was measured is a guess.
- **A draft plan to confirm the chosen version properly** is written but deliberately not frozen, for the integrator to review. It says plainly that the number it would check was already printed by the trial run, so passing it would not be news; a truly unseen test needs the second set of pilot simulations now running, or new locations.
- **A data error found in an older script, not fixed here:** the script that turns the soil input into soil properties reads soil type 13 as light clay, but in the original model's own settings type 13 is rock and ice. 3,180 of the 67,420 cells have it. None of the 200 pilot locations does, so no registered result is affected, but any global use of that script would be wrong for those cells. The new code uses the correct values.
- **More inputs built from the day-by-day weather (31 + 16 new quantities), and a trial of ways to predict the forest's carbon at the stored global spin-up's settled state — which lift the share of places predicted within the acceptance band from 43 % to 62 % (all 56,986 places with trees, two runs of the original model as truth), where a second run of the original model manages 86 %. Still far from "as good as a rerun"; an exploratory result, not a registered one.** The new inputs are the original model's own fire rule applied to a simple soil-water budget, the yearly water shortfall and its worst year, the coldest, warmest, driest and wettest year of the 30, the length and sunlight of the growing season, and the sunlight each plant type can use given the model's own temperature response of photosynthesis, with and without water limitation. None uses the location or CO₂. They exist for all 6,000 pilot simulations and all 67,420 land cells, for the spin-up's climate (1901-1930) and for 1970-1999. **Hard check passed exactly:** for the 200 unperturbed pilot runs they equal, to the last digit, the values computed from the global weather file, and adding them changed none of the earlier 120 inputs.
- **What was tried, chosen on three of the five groups of places only (the other two were only printed):** the new inputs (the largest single gain), training on each seed of the years that are actually scored, first predicting whether a place carries trees, an absolute-error loss, a larger and tuned learner, adding the pilot simulations to the training rows, averaging five model copies, and the photosynthesis-light inputs each helped; a floor that turns tiny predictions into zero, and mixing two error measures, did not. The procedure itself first reproduced both registered results exactly. On the two held-back groups (20,123 places) the chosen version lands 60.6 % within the band against 86.9 % for a rerun on the same places (42.6 % for the registered version); it explains 98 % of the variation in log carbon.
- **Where it still fails:** low-carbon places (under 100 g C per m², 34-38 % in band against a rerun's 77-89 %), places where trees and grass share the land (48-57 %), and places whose carbon was still drifting inside the scored centuries. The best possible deterministic prediction (each place's own average of the two runs) would land 98 %; reaching a rerun's 86 % needs the typical error to shrink from about 7-8 % to about 5 %.
- **Trained on the pilot alone — the emulator proper — the same recipe reaches 38 % on the development groups and 36 % on the held-back ones** (the registered pilot-trained version: 24-26 %), so the 200 pilot places remain the main gap for the emulator itself.
- **A draft plan to confirm the chosen version on the two held-back groups**, with the four comparison baselines measured there, for the integrator to review. It states outright that the answer is already known from the trial and expected to fail the rerun test.
