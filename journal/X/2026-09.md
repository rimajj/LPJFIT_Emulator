### Addendum — the two local defences were both silently absent

The record went in at 131 lines against a 120 cap and CI caught it, which cost a merge cycle. Both
local defences that exist for exactly this failed, independently, and I got the diagnosis wrong the
first time before reading the code.

I first told the owner the `ALLOW_LOGIN_HEAVY=1` prefix had bypassed the commit guard. That was
wrong: the guard's command regex matches a leading `VAR=1` assignment perfectly well. The real cause
is worse and has nothing to do with the escape hatch. `commit-guard.sh` is a PreToolUse hook, so it
runs BEFORE the command — and it reads the staged set and exits 0 if it is empty. For `git add X &&
git commit -m Y` as one command, the index is still empty when the hook looks. Verified by feeding
the hook that exact payload with an empty index: exit 0, no checker run. Every commit this session
used that form, so none of them was checked by budgets, ownership, experiments or secrets. The
documented `ALLOW_COMMIT_GUARD_SKIP=1` escape at least leaves a `Guard-skip:` trailer that CI counts;
this leaves nothing.

Second, `tools/check_budgets.py` with no arguments falls through to `git ls-files`, so a brand-new
untracked file is invisible to it. That is why my own pre-commit check passed at 131 lines and again
at 122 — the file was untracked both times. Explicit-path or `--staged` both catch it. The default
path is the one a human runs by hand, which is the one that should be safest.

Fixes requested in `20260909-X-the-commit-guard-sees-an-empty-index.md`, in order, with the trap in
the cheap fix named: denying on "empty index plus a git add in the command" still lets `git commit
-am` through, so only moving the checks into `.githooks/` removes the class.

On the record itself: I rewrote it in place rather than superseding it. The immutability guard exists
so a published audit trail cannot be quietly rewritten, and I think it was right to hesitate — but

### Addendum 2 — the Stop hook that blocked the handoff is the bug the integrator is mid-fixing

The session-end gate blocked with "made 10 commits but did not refresh its handoff". The handoff had
been refreshed, in 41037b9, the last commit. Running the hook's own test by hand found 5 matches, so
its condition was true and it should have exited 0.

Cause, confirmed by reading the integrator's uncommitted diff in the shared checkout: the gate was

    git log origin/main..HEAD --name-only --format=%B | grep -qE "lines/$LINE/STATE.md|..."

under `set -o pipefail`. `grep -q` exits at its FIRST match, `git log` is still writing, so `git log`
takes SIGPIPE, pipefail promotes 141 to the pipeline's status, and the `if` is false no matter how
good the handoff is. It fails HARDEST for sessions doing the right thing: `git log` is newest-first,
so refreshing the handoff in your last commit puts the match at the top of the stream and guarantees
the earliest possible SIGPIPE. Their comment also notes it only reproduces when run as a FILE, not
typed into a subshell — so an inline check would have "proved" it fixed while it was not.

The loop closes on itself: that uncommitted fix is the same work that made merge.sh refuse. One
commit by whoever owns it clears the merge path AND the false handoff block. That is now the first
line of NEXT, because it is the single highest-value action available to anyone tomorrow, and it
costs one commit.

Worth naming the pattern, since it is four for four today: the gate selector reads a different diff
than GitHub; the commit guard reads the index before staging; check_budgets reads tracked files and
misses new ones; the stop gate reads a pipeline status that SIGPIPE has already poisoned. Every one
is a check whose observation is taken at the wrong moment or over the wrong set — not a check with
the wrong rule. And each one fails OPEN or fires FALSE silently, which is why they accumulated.

## 2026-09-10 — the bar was sealed without a ceiling, so I went and measured one

Line X came back level with main: the integrator committed the Stop-hook fix and formatted line T's
three files, which cleared both of yesterday's blockers. Nothing of mine was owed except waiting on
line T, so I went looking for what I had left undone rather than idling on their critical path.

What I had left undone was the ceiling. I sealed X5 with a bar of 0.225690 and no statement of what
perfect means -- the exact omission line T caught in the drift test (a conjunctive pass rate read
against an implied 100 % when a third real seed reaches 25 %) and the one X3 had already fixed for
itself (0.538490, not 1.0). I wrote that gotcha into STATE.md yesterday and then committed the same
error one experiment later, which is worth noticing about myself: writing a rule down is not the
same as applying it, and the pre-registration schema has no ceiling field to force it.

The argument is short. The model is stochastic, the target is a difference of two single runs, so
the target carries noise a perfect emulator cannot predict; ceiling = 1 - Var(eps_p - eps_0)/SS.
sigma comes from the only two-seed pair at these cells, the ground truth historical seeds 1 and 2.
Answer: 0.8697, so the bar is not merely reachable, it is about a quarter of the attainable range.
High because the perturbations are large (+6 K, x0.7 precip) and the response dwarfs the noise --
the opposite of X3 and of t3, where signal and noise were comparable and the ceiling collapsed.

It is a LOWER bound on purpose: a cell control and perturbed arm share a random seed, so the noise
partly cancels by an amount nobody has measured. 0.9349 at half-cancellation, 1.0 at full. I costed
the fix rather than hand-waving it -- 20 cells x 30 climates x a second seed is ~34 core-hours at
line D own measured rate, 10 % of what the pilot cost. Asked for; not blocking, since every value
of rho clears the bar.

The second measurement is the one I did not go looking for. The same two reads let me ask whether
the pilot SINGLE-CELL control spin-up reproduces the GLOBAL run at the same cell -- line D proved
the neutral design point is a no-op in the forcing BYTES, which is not the same claim. First pass
looked alarming: |pilot - seed1| is ~1.4x the two-seed gap everywhere and 3.6x for soil carbon, with
only 20-46 % of cells inside the spread. I nearly wrote that up as "the corpus is not the same
model". Then I added the signed median, which is the measurement that actually discriminates, and
re-ran. Six of seven quantities have signed offsets of 0.00-0.70 % against a seed-to-seed control of
the same size: unbiased, just a wider draw. Only soil carbon is real, at -2.68 % against -0.36 %.

So the honest finding is narrow and it survives: the pilot is a different draw, not a different
model, EXCEPT in the slowest pool, where it is systematically light. That does not threaten the kill
test -- a within-pilot paired contrast cancels a per-cell offset exactly, which is precisely why the
paired design was chosen -- but it does threaten anyone training on pilot levels and scoring against
ground-truth levels, which is what X2 and X3 do. That is now a line T warning in NEXT.

Lesson worth keeping: the absolute-gap table said "different model" and the signed table said
"different draw". Scatter and bias are not the same finding, and the first table I computed could
not tell them apart. One extra column, one re-run, and the conclusion inverted.

The answer turned out to be sharper than "no, that would be too strict". The band is
`max(10 %, spread) × |truth|`, so a zero truth gives a band of exactly zero — I verified this
against the shipped functions rather than reading it off the formula, and `1e-9` misses. Then the
corpus said 45.6 % of cell–PFT pairs are exactly zero and **every one of the 6,000 rows holds at
least one**. So the conjunction would score ~0 for any continuous predictor while the
template-copying synthesiser passes all seven trivially: a statistic anti-correlated with the
capability it was added to measure. That is a stronger objection than "strict", and it is the one
worth recording, because "too strict" invites someone to loosen the band instead.

Composition moves to the response basis as one bounded scalar (`comp_shift`, total variation) whose
frozen arm is pinned analytically at 0.0. Note what this buys: the synthesiser's disclosed
limitation stops being a caveat in a comment and becomes a null someone has to beat.

**The two "verdict metrics block is STALE" loops replayed at every session start are false.** The
hook calls bare `python3` (3.9, no `tomllib`) with stderr sent to `/dev/null`, so the checker

## Line X gotchas

* **Derive the nulls before designing the statistic, not after.** Three times now this has caught a
  dead experiment before sealing: X4's nulls were mutually indistinguishable; X5 would have
  inherited X1's `> 0.050` threshold, which **the best null itself satisfies by 0.000080**; and
  composition as a level would have been aced by the one arm it was meant to catch.
* **A threshold is derived from the nulls, never inherited from a sibling experiment.** The no-power
  rule scores each null on the model's comparator, so under `model_minus_best_null` what matters is
  the gap between the best null and the *runner-up*, not the best null's own value.
* **A BIG best-null-to-runner-up gap is the BAR, not free headroom** — and it looks like the
  opposite. X6's 0.1435 gap was offered as evidence the test was well-powered; it is, but it forces
  the threshold up by the same amount, because a null that far ahead is one that would pass its own
  test. Compute every null's margin-over-best-other at **every blocking radius**: X6's binding case
  was the 5° arm (0.1482), not the primary 15° one.
* **A null set can be complete and still miss a CLASS.** X5's seven are all information-free by
  construction, so none was a *learned-but-treatment-blind* competitor — and that arm scores above
  the bar. Before sealing, ask what a model that learned the data but not the treatment would score.
* **A relative band is meaningless where the truth can be zero** — exactly 0 wide, so only an exact
  `0.0` passes. Bounded fractions need an **additive** floor beside the multiplicative one.
* **Every skill number needs a CEILING arm, and it is never 1.0.** Measured: 0.5585 on the 22-way
  conjunction, 0.869730 on the pilot response, 0.863852 on composition. A two-sample spread
  underestimates dispersion and a conjunction compounds it, so quoting a shortfall against an
  implied 100 % overstates it. A wider conjunction has a *lower* ceiling — re-measure, never carry.
* **A metric a null also passes has no power**, and the check is sensitive to how the nulls are
  chosen: two of similar strength protect each other, one strong null beside weak ones trips it.
* **State the blocking radius with every spatial claim.** At 5° blocks the address null flipped from
  −0.142 to +0.120 on the X2 response. On pilot-v1 it moves the nulls by <0.003, because 200 cells
  sit in 164 tiles — a property of the cell design, so re-check it per corpus, never assume it.
* **Check that a leg's two model runs are actually two runs before deriving anything from them.**
  Identical runs give a spread of zero and `max(10 %, spread)` silently becomes a bare 10 %. This
  fired for real: the high-emissions second seed was a byte-clone until 2026-09-14.
* **Suspect the plumbing before believing a surprising verdict.** `x or default` treats a legitimate
  0.0 as missing and 0.0 is exactly what an analytic null returns; and a non-zero exit is not a
  finding, since a checker that cannot import its dependencies exits 1 exactly as a real violation
  does. Run tools with the project python (`config/paths.yaml`).

## 2026-09-23 — a replacement for the emitted-restart test, measured and sealed (int/score)

**What changed and why it works now.** The retired test asked a yes/no per target and every null
answered "no" 99.5 % of the time. C1 keeps the band, the floor, all 19 varying quantities and all
29 climates, and scores each target by its worst quantity *in band units* instead of a bit; the
decision statistic is -log(median worst error). Chosen before scoring anything, for having no free
parameter (a mean of logs would need an epsilon and a cap, i.e. two thresholds). It separated the
very predictions that had collapsed: on X4's own basis (whose six conjunctive values reproduced
exactly first) the six nulls fall in the physical order at 15 deg, and on the two-run v2 basis at
both 15 and 5 deg, smallest gap 0.038. The one weak spot: same-climate analogue vs forest next door
are tied under the tile bootstrap (ordered in 72 % of draws). Irrelevant to the decision, which only
needs the best null clearly first (99.4 %).

spin-ups finished while I worked, but nobody had decoded them, and the decode writes into a
